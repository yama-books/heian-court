# DESIGN DECISIONS — 決定と未決定の境界
更新: 2026-11-04 JST／正本の設計判断。採用日以前のアイデアは会話由来、GitHubの初回文書化は本日。

## 採用済みの基本方針
| ID | 判断 | 根拠・理由 |
| --- | --- | --- |
| D-01 | 「A＋B」＝一人用人生シミュレーション＋自律NPC箱庭を基本にする | ゲームの面白さをサーバーや同時参加に依存させない |
| D-02 | 史実重視、最初の舞台を一条朝・西暦1000年前後とする | 時代差を混ぜず、人物・権力・職務・親族を検証できる |
| D-03 | 官位・官職と非公式な権力は別々に表現する | 序列＝政治力ではない |
| D-04 | 出自・性別に整合した進路を設け、運命任せ／生き方選択／立場指定を入口候補とする | 偶然性と歴史学習の両立 |
| D-05 | 他プレイヤーはランキングでなく、公開された来歴を発見・閲覧する | 多様な人生を比べる |
| D-06 | 自由チャットを作らず、定型文の消息を検討する | 不適切なメッセージやトラブルを抑える |
| D-07 | 共有世界はリアルタイム同期でなく匿名・遅延した宮廷の気運として作用する | 低コストかつプレイヤーの人生を保護 |
| D-08 | 怪異は史実・信仰・文学・創作に区別する | 史実を捏造せず源氏物語的な体験を活かす |
| D-09 | 初めは静的Web、オンライン共有は後続 | 非ローカル・小さな試作を優先 |
| D-10 | GitHub Pages公開・実装・オンライン交流の本番化は、それぞれ別工程の承認対象 | 無断公開・複雑化を防止 |

## 未確定（勝手に実装仕様へ昇格させない）
- 正式アプリ名・ロゴ・画風・UI、和歌の難易度と用字
- 選択可能な性別・出自の個数と抽選重み、プレイ開始年の最終確定
- ターン長（四季案）、寿命・病気・死亡の処理、NPCの意思決定モデル
- 何が史実固定で何が創作可能か、史実改変モードを作るか
- 実在人物と架空人物の関係制限、女性の各経路の詳細
- オンライン公開同意、削除、保存期間、認証、多重参加対策、集計の更新間隔・閾値
- Workers/D1導入、無料枠・ライセンス・公開時の保守担当
- APP-ID。Session Deck台帳と既存プロジェクトの採番に不整合が見えるため、正本照合後に決定する

## この設計基準の改訂規則
- 「採用済み」は会話で了承した方向性であって、**機能実装済み**を意味しない。
- 大きな変更は理由・影響先・未検証事項を短く追記し、`GAME_DESIGN`や`ASYNC_SOCIAL`と整合させる。
- 歴史の確定データを更新する場合は`HISTORICAL_RESEARCH`の出典・時点基準を優先する。
